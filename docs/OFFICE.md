# Alt8Mail Office

Alt8Mail Office is the OnlyOffice Document Server integration for the workspace.
Phase 1 built the lifecycle, gateway, JWT secret and feature-flag plumbing.
Phase 2 added the Cabinet editor, JWT-signed editor configuration, verified
callbacks, idempotent saves, immutable versions and PDF conversion. Phase 3 adds
guest Office links, compose/attachment/calendar integration, co-editing through
shared edit links, and an in-editor Alt8Mail AI assistant. Phase 4 adds internal
user/group sharing, organization Office policies, DLP scanning on save, legal
hold protection, eDiscovery export and text version comparison. Phase 5 adds
remote Office hosts over SSH with agent bootstrap and an HTTP-over-SSH tunnel.

## Architecture

```text
Browser                                  Alt8Mail API
  │                                         │
  ├─ https://mail.example.com               ├─ GET  /api/office/config
  │    Cabinet → isolated editor page       ├─ POST /api/office/documents/{id}/open
  │         │                               ├─ POST /api/office/callback
  │         ▼                               ├─ GET  /api/office/content
  │    /office-editor (same origin)         │
  │         │                               │
  │         └── DocsAPI ──────────────┐     │
  │                                   ▼     │
  └─ https://office.example.com   nginx office gateway
                                      │
                                      ▼
                              OnlyOffice Document Server
                              127.0.0.1:8082 (Docker)
                                      ▲
                                      │
                              a8m-office-agent
                              (loopback lifecycle API)
```

OnlyOffice Document Server is intentionally separate from the mail host. It
runs Node.js, PostgreSQL, RabbitMQ and Redis inside the official Docker image.
Do not put it on a 4 GB mail server.

The browser never loads the OnlyOffice browser API into the main webmail shell.
Cabinet frames a small same-origin host page at `/office-editor`; nginx applies a
dedicated CSP to that page only. The mail application keeps its strict
`script-src 'self'` policy.

Because the host page is same-origin with webmail, the Document Server browser
API is trusted code: a compromised Document Server could act with the signed-in
user's origin privileges. Run the Document Server on a host you control, keep it
patched, and treat its compromise as a webmail compromise. The editor page is
deliberately minimal and contains no mail content of its own.

## Requirements

- Docker Engine and the Docker Compose plugin on the Office host.
- For remote deployment: SSH access from the Control Plane to the Office host,
  a root or passwordless-sudo account, systemd, a CPU architecture matching the
  Control Plane build, and the `a8m-office-agent` binary in the same release bin
  directory as the Control Plane. Docker Engine, the Compose v2 plugin, `nginx`
  and `certbot` may be installed automatically on Debian/Ubuntu during the
  remote install. SSH TCP forwarding must be allowed; the agent is reached
  through a `direct-tcpip` tunnel to remote loopback.
- A dedicated `office.<domain>` A/AAAA record pointing at the Office host before
  installation. The Control Plane blocks install/reconfigure/enable until DNS
  resolves to a known local or configured public address.
- A valid TLS certificate for that hostname. Control Plane can select an existing
  certificate or issue a new Let's Encrypt certificate through the Office agent
  using the HTTP-01 webroot challenge. `certbot` is required on the Office host
  for automatic issuance and can be installed by the remote preparation step.
  Existing certificates are rejected unless their SAN list covers the public
  Office hostname.
- The webmail public URL (`ALT8MAIL_PUBLIC_URL`) must be reachable from the
  Document Server. OnlyOffice fetches document content from that origin and
  posts save callbacks back to it.
- At least 4 GB RAM for Document Server, plus the mail host. A separate 4–8 GB
  Office host is the supported production shape; local Docker is acceptable only
  when the host has enough memory.
- The OnlyOffice image tag you intend to support. The default is
  `onlyoffice/documentserver:9.4.0.1`; pin a tested tag and verify it against
  Docker Hub before production.
- An OnlyOffice licence appropriate for your concurrency. The community image
  has connection limits; Alt8Mail does not manage OnlyOffice licensing. To use an
  enterprise licence file, place `license.lic` in
  `/var/lib/a8m-office/data/`; the agent mounts that directory at the Document
  Server's `Data` volume.

## Local agent installation

The release includes the binary and systemd unit:

```bash
sudo systemctl enable --now a8m-office-agent
sudo systemctl status a8m-office-agent
```

The unit reads `/etc/a8m/office-agent.env` when present and defaults otherwise.
The agent creates `/etc/a8m/office-agent-token` on first start if the installer
did not create it. The token is `root:a8m`, mode `0640`, and is used only by the
Control Plane on loopback.

The agent does not install Docker or certbot. If Docker is missing, install
actions fail with a clear error. If automatic TLS is selected and certbot is
missing, certificate issuance fails before the container is changed. The compose
file, state and JWT secret may already have been written by then, but no
container is started.

Automatic certificate issuance uses:

```text
OFFICE_AGENT_CERTBOT=certbot
OFFICE_AGENT_CERTBOT_DIR=/etc/letsencrypt/live
OFFICE_AGENT_CERTBOT_WEBROOT=/var/www/certbot
```

The systemd unit grants write access to `/etc/letsencrypt`,
`/var/lib/letsencrypt`, `/var/log/letsencrypt`, `/etc/nginx` and the ACME
webroot. The certificate is named `a8m-office-<hostname-with-dashes>` and is
reused on later installs/reconfigures. Certbot's renewal configuration keeps the
nginx reload deploy hook.

## System Control workflow

1. Open **Infrastructure → Office**.
2. Choose **Local Docker host** or **Remote server over SSH**.
3. For a remote host, provide the SSH hostname/IP, port, system user, private key
   or password, optional key passphrase, remote public IP when NAT is used, and
   pin the SSH host key fingerprint. The Control Plane SSHes to the host, runs
   the preflight, uploads `a8m-office-agent`, installs its systemd unit and keeps
   the agent API on remote loopback behind an SSH tunnel.
4. Enter the public URL, for example `https://office.example.com`.
5. Run **Install preflight**. The first remote probe only discovers the SSH host
   key; the remaining rows stay **Pending** because credentials are not sent to
   an untrusted host. Review the fingerprint, including its key type, and click
   **Trust fingerprint & run checks**. Certificates may publish several host
   keys, so an OpenSSH client can display a different fingerprint if it chooses
   a different algorithm. After trust, the remote checks DNS against the
   remote/public address, SSH privilege (root or passwordless sudo), memory,
   Docker/Compose, nginx, certbot, systemd, disk, CPU architecture and the SSH
   host key. Installation is blocked unless the deployment target passes.
6. For a standalone/empty remote server, leave **Install missing dependencies
   automatically** enabled (the default). During **Install / reconfigure**, the
   Control Plane installs only the missing pieces from `Docker Engine`, the
   Compose v2 plugin, `nginx` and `certbot` through the remote host's `apt-get`,
   enables Docker/nginx, and verifies them before bootstrapping the agent. The
   package step is idempotent, waits on apt/dpkg locks, retries `apt-get update`,
   and fails with the remote command output if a package cannot be installed.
   It requires a Debian/Ubuntu host with root or passwordless sudo. When
   auto-install is off, preflight blocks on missing packages and an explicit
   **Install missing packages** button runs the same preparation. systemd and
   SSH privilege cannot be installed this way.
7. Choose the OnlyOffice image tag.
8. Choose TLS: **Automatic Let's Encrypt** (default), an existing local
   certificate, keep the current gateway certificate, or install without a
   public gateway. Remote deployments support automatic Let's Encrypt, keep and
   no-gateway; local certificate paths cannot be used on a remote host.
   Automatic mode requires a Let's Encrypt account email and runs certbot on the
   Office host through the agent.
9. Click **Install / reconfigure**. The agent issues the certificate when
   automatic TLS is selected, writes a temporary HTTP-01 challenge site, pulls
   the image, starts the container, waits up to three minutes for `/healthcheck`,
   then writes `/etc/nginx/sites-available/a8m-office`, validates nginx and
   reloads it.
10. Start/stop/restart/update from the lifecycle card. **Reconfigure gateway**
    re-runs the deployment preflight and can issue or replace the certificate.
11. Enable **Office for webmail** only when the service is running, healthy and
    has a configured gateway. Enabling also re-checks the deployment preflight.

Remote SSH credentials are sealed with AES-256-GCM using `CONTROL_SECRET_KEY`
and are never returned by the API. The SSH host key must be pinned; a first
preflight only reports the fingerprint and runs no remote commands until the
operator trusts it. After bootstrap, every lifecycle request uses an HTTP client
whose transport dials the remote agent through the SSH connection; port 8098 is
never exposed publicly.

After a remote install or JWT rotation, the Control Plane reads the remote
`/etc/a8m/office-jwt-secret` over SSH and writes the same value to its local
`CONTROL_OFFICE_JWT_SECRET_FILE`. This keeps the webmail editor-config signer and
the remote Document Server using the same JWT secret.

Rotating the JWT secret recreates the container. Open editor sessions are
invalidated; the webmail API reads the new secret from the shared file.

The gateway's exact `/`, `/welcome` and `/welcome/` locations redirect to the
webmail portal. Reconfigure the gateway after upgrading so the generated nginx
site includes the redirect; an older gateway continues to show the OnlyOffice
welcome page at the root URL.

## Webmail Office workspace

- The editor header has **Minimize**, **Maximize/Restore** and **Close** controls.
  Minimize keeps the editor loaded and adds a tab to the Office dock above the
  status bar. The dock survives sign-out and sign-in in the same browser; closing
  the tab destroys the dock entry.
- The editor follows the webmail theme at open time and receives live
  `theme-light`/`theme-dark` updates when the account theme changes.
- The rail exposes **Docs**, **Sheets** and **Slides** launchers. Each opens a
  draggable Office home with a blank-create action, recent Cabinet files of that
  type, and recent inbox messages carrying a matching attachment.
- The **New mail** split menu also creates Word, Excel and PowerPoint documents
  directly.
- New documents carry the author's full name, the document title and the custom
  `Platform = Alt8Mail Workspace` property in `docProps/core.xml` and
  `docProps/custom.xml`.
- Native selects use a shared modern, theme-aware control style; the new-document
  dialog uses selectable type cards with Word/Excel/PowerPoint iconography.

## Office monitoring

When monitoring is enabled in **System Control → Office**, the Office agent
samples its container through Docker and its host through `/proc` and `df`. No
shell is exposed. The Office page shows live CPU, memory, network, block I/O,
PIDs, load, uptime, root disk and the `/var/lib/a8m-office` data disk; the
dashboard adds an Office Document Server performance card. The Office page polls
every 12 seconds while visible; the dashboard refreshes with its normal interval.

Disable monitoring with the switch in the Office performance card. The setting
does not stop the Document Server or the agent. Remote deployments need a
reconfigure after upgrading to upload the agent build that includes `/metrics`.

## Remote deployment

Remote mode is a first-class deployment target, not a pointer to a pre-installed
agent:

1. The Control Plane connects to `host:port` as the supplied SSH user using a
   sealed password or private key. The SSH host key must be pinned after the
   first fingerprint-only probe.
2. Preflight runs fixed commands to check Linux, CPU architecture (must match the
   Control Plane build), root or passwordless sudo, RAM, free disk, Docker and
   the Compose plugin, nginx, certbot, systemd, remote/public addresses and the
   Office DNS record.
3. Bootstrap creates `/opt/a8m-office`, uploads the matching
   `a8m-office-agent` binary from the Control Plane release, writes the agent
   environment, a generated bearer token and the systemd unit, then starts and
   health-checks `a8m-office-agent` on remote loopback.
4. The Control Plane stores the SSH credential, passphrase and agent token
   sealed with AES-256-GCM. The SSH secret is decrypted only while opening a
   connection. The agent token is sent only through the SSH tunnel.
5. Every later status, install, start/stop/restart/update, gateway, log and JWT
   rotation request uses HTTP over the SSH connection to `127.0.0.1:8098`. The
   remote agent port is never exposed publicly.
6. The remote agent performs the same Docker Compose, nginx and certbot
   operations as a local install. After install or JWT rotation, the Control
   Plane reads the remote JWT secret and writes it to its local webmail secret
   file so editor config signing stays in sync.

Docker Engine, the Compose plugin, nginx, certbot, systemd and an SSH account
with root or passwordless sudo are required. A standalone Debian/Ubuntu server
can start empty: preflight distinguishes missing packages from hard blockers,
and the install prepares them automatically when the remote auto-install option
is enabled. Other distributions must install those packages manually. systemd
must be provided by the base image and cannot be installed by the Control
Plane.

The remote preflight and install APIs accept `installDependencies` (default
`true`). It is honored only when `apt-get` is available; missing packages are
installed during the install before the Office agent is bootstrapped. Set it to
`false` to require a pre-provisioned host.

## Cabinet editor

Supported formats:

| Editor | Extensions | New document |
| --- | --- | --- |
| Word | `docx`, `doc`, `odt`, `rtf`, `txt` | `docx` |
| Spreadsheet | `xlsx`, `xls`, `ods`, `csv` | `xlsx` |
| Presentation | `pptx`, `ppt`, `odp` | `pptx` |
| PDF viewer | `pdf` | — |

Legacy binary formats (`doc`, `xls`, `ppt`) open in view mode. Editing and
saving uses the OOXML and ODF formats. PDF conversion is available for every
non-PDF Office format.

Office editing is available for files stored in **Alt8Mail Drive**
(`provider_id = a8m`). Connected Dropbox, Google Drive and S3 files remain
read-only in Office; copy them to Alt8Mail Drive first. The signed content URL
and version files stay inside the Cabinet upload directory.

Opening a document:

1. Webmail calls `POST /api/office/documents/{fileId}/open`.
2. The API ensures an `office_documents` row, reuses the current Cabinet blob
   for the initial immutable version, and mints two HMAC-signed URLs:
   - a 10-minute content URL for the Document Server to download;
   - a 24-hour callback URL for save events. Reopen documents that stay in the
     editor longer than the callback window.
3. The API returns a JWT-signed DocsAPI configuration containing the editor
   mode, user, key and callback URL. The secret never reaches the browser.
4. `/office-editor` loads `https://office.<domain>/web-apps/apps/api/documents/api.js`
   and creates the editor inside `#editor`.
5. On close, force-save or autosave, the Document Server posts a JWT-signed
   callback. Alt8Mail verifies the JWT, validates the document key, downloads the
   saved file and writes a new immutable version.

Every editor save increments `files.version`. The current `document.key` changes
after each save so the next open starts a new Document Server session.

### Idempotency

`office_callback_events` uses a unique `(document_key, status, event_key)` key.
OnlyOffice retries are acknowledged without writing duplicate versions. A save
still marked `processing` returns `{"error":1}` so the Document Server retries,
and a crashed save older than five minutes can be reclaimed.

### Versions and restore

- **Versions** in the file detail and editor header lists every saved version.
- A version can be downloaded as `<name> (vN).<ext>`.
- Restoring a version creates a new latest version; earlier versions are never
  deleted. Close the editor before restoring.
- Deleting the Cabinet file removes its Office version files from disk.

### PDF conversion

`POST /api/office/documents/{id}/convert` sends a JWT-signed conversion request
to the Document Server, downloads the resulting PDF and stores it as a new
Cabinet file. Conversion runs inside the normal request budget and is bounded
at 50 seconds.

## Guest Office links

Existing Cabinet share links (`/files/s/<token>`) gain an **Open in Office**
action when the shared file is an Alt8Mail Drive document and Office is ready.

- **View links** open the Document Server in read-only mode.
- **Edit links** open in edit mode and save new immutable versions back to the
  owner's Cabinet. OnlyOffice co-editing is enabled for these sessions.
- Recipient-restricted links use the existing 12-hour share access cookie. A
  guest must confirm the recipient email before the Office button appears or the
  guest endpoint accepts the request.
- Locked links, revoked links and expired links cannot open or save Office edits.
- Saves are re-checked against the live share row, so revoking an edit link stops
  further saves even if an editor is still open.
- Guest opens and saves are written to the workspace audit with the guest email
  (or “Guest link”) as the actor.
- The guest editor runs from the same `/office-editor` host but calls
  `POST /api/public/shares/{token}/office`; no Alt8Mail account is created.

## Internal sharing and enterprise controls

### Internal sharing

The Cabinet share dialog has a second, owner-only section for colleagues and
groups. It creates grants in `file_permissions`; it does not create a public
link.

- A grant is for one user or one group, with **view** or **edit** access. Granting
  the same person or group again updates the existing grant.
- Group membership is resolved live. Removing someone from a group, or revoking
  the grant, takes effect on the next file, Office, content, version or save
  request.
- Shared files appear in the recipient's Cabinet with a **Shared with you**
  marker and the owner's name. Shared recipients can preview, download and (for
  Office files) open or edit according to the grant. They cannot rename, move,
  delete, star, create link shares or manage permissions.
- Shared Office opens use the owner's document record and content capability,
  but the callback token also carries the editor's user ID. The callback
  re-checks the live user/group edit grant before storing a version.
- External link recipients are not disclosed to internal recipients.
- The organization can disable internal sharing with **Policies → Office →
  Internal sharing**. The API rejects new grants and the dialog hides the
  section.

### Office policy

Customer Admin → Policies → Office stores these fields in the tenant policy:

| Field | Default | Effect |
|---|---|---|
| `enabled` | on | Office is unavailable when off. |
| `internalSharing` | on | User/group Cabinet grants. |
| `externalEditing` | on | Guest edit links; off forces guest links to view-only. |
| `ai` | on | The in-editor AI panel and `/api/office/ai`. |
| `dlpOnSave` | on | DLP inspection of saved Office text. |
| `versionRetention` | 0 | Keep this many newest versions per document; `0` keeps all. Older version blobs are pruned after a save. |
| `allowedGroups` | empty | If set, the user must belong to one listed group. |
| `allowedDomains` | empty | If set, the user or verified guest must match one domain. |

When both audience lists are set, a user must match a domain **or** a group.
Guest links only use the domain check; group membership is internal-only.
Disallowed users receive `403 OFFICE_POLICY` from Office endpoints, and
`GET /api/office/config` reports `enabled: false`.

### DLP on save

When `office.dlpOnSave` and the tenant DLP policy are both enabled, each save
callback extracts plain text from the new document and runs the existing DLP
rules against the file name (subject/attachment) and the extracted text (body).

- A **block** rule fails the save; the current version remains in place and the
  callback audit records `office.dlp_blocked`.
- Label and warn rules record the effective classification, warnings and matches
  on `office_document_versions`. The latest classification is also stored in the
  file metadata and shown as a chip in Cabinet and version history.
- DOCX, XLSX, PPTX and ODF text is read from the document XML. TXT, CSV and RTF
  are read directly. Legacy DOC/XLS/PPT use readable string runs. PDFs have no
  text extractor in the dependency-free build, so a PDF save is evaluated using
  the file name and tenant default classification only. A failed extraction is
  recorded as a version warning instead of being silently ignored.
- Zip extraction is bounded to 24 MB of uncompressed XML and 400,000 output
  characters, which protects the API from document zip bombs.

### Office quota and version retention

Office uses the same Cabinet storage policy as other Cabinet writes. The policy
is resolved from the organization, domain and user overrides, and includes
combined mailbox+Cabinet or separate Cabinet allowances.

- New documents and PDF conversions check the quota before writing.
- Every editor save checks the document owner's Cabinet quota before the new
  immutable version is written. A blocked save leaves the current version
  intact, is audited as `office.quota_blocked`, and returns a save error to the
  editor instead of silently exceeding the allowance.
- Restoring a version uses the same quota check.
- The initial version of an existing Cabinet file reuses the existing Cabinet
  blob instead of creating a second copy, so opening a document does not
  double-charge the quota.
- `versionRetention` keeps the newest N versions per document. When a save or
  restore prunes older versions, their storage is released after the database
  transaction commits. The quota check accounts for the space that will be
  released by that same operation. `0` keeps every version; the maximum is
  1000.

### Legal hold and eDiscovery

- Cabinet file deletion is rejected with `409 LEGAL_HOLD` while the owner is
  covered by an active tenant-wide or user legal hold. The attempt is audited.
- Customer Admin → Compliance now offers **Export Office CSV** beside the mail
  export. It honours the current keyword, mailbox, date and classification
  filters and includes the Office format, current version, DLP classification,
  DLP warnings and last-saved time for each document.
- The export is recorded as `admin.office_ediscovery_exported` in the admin
  audit log.

### Advanced audit

Office activity is written to the durable `workspace_audit` stream and the
tenant `audit_log` stream used by SIEM:

- created, opened, saved, guest opened/saved, shared-editor saved
- DLP-blocked and quota-blocked saves
- restored, reviewed and compared versions
- downloaded versions
- converted documents
- AI assistant use
- internal permission grants and revocations

Webmail Settings → Audit log now has an **Office** filter and an Office CSV
export. Customer Admin → Audit log has an **Office activity** source with its
own search and CSV export. Office and internal-permission events are mirrored
into `audit_log`, so the SIEM webhook receives them alongside mailbox and admin
events. The workspace audit CSV is also available at `/api/workspace/audit.csv`.

### Version comparison and review

Version history offers **Compare** on older versions and a From/To picker. The
API extracts text from both immutable versions and returns a bounded line diff
(up to 1,500 lines and 800 output rows). Formatting is intentionally ignored;
comparison is a review aid, not a pixel diff. PDF and unreadable binary versions
return `422 OFFICE_COMPARE`.

Owners and users with edit access can mark any version **Approved** or
**Changes requested** from version history. The decision stores the reviewer,
timestamp and optional note against that immutable version, so later saves do
not erase it. Review decisions are audited as `office.version_reviewed`. Shared
view-only recipients can read the review status but cannot change it.

## Compose and mail attachments

- Received Office attachments get an **Open in Office** action in the message
  reader. The attachment is saved to Alt8Mail Drive first (deduplicated by
  `attachmentId`), then opened. The original mail attachment is never modified.
- The compose attachment picker offers **New Office document**. It creates the
  document in Cabinet, attaches a copy to the draft and opens the editor.
- Compose attachments also expose an Office action. Files are saved to Alt8Mail
  Drive on demand. When the editor closes, the compose attachment is refreshed
  from the updated Cabinet file so the sent message carries the latest content.
- After a compose attachment is edited, the editor host reports its saved state
  to the webmail shell. The shell refreshes the attachment immediately and also
  polls for up to 30 seconds for a lagging Document Server callback, replacing
  the draft attachment and scheduling a draft save.
- Editing a received mail attachment writes to the Cabinet copy; the original
  message is never mutated. When the updated copy is saved, the owner gets a
  **Reply with file** action that opens a reply and attaches the new version.
- Attachments in Junk remain blocked, and delegated compose windows do not expose
  Office actions.

## Calendar attachments

Calendar events already support Cabinet file attachments. Phase 3 adds an Office
action to each attached document in the event editor. The file is opened from its
live Cabinet record; changes become new versions in Cabinet. Event attachment
links remain metadata snapshots, so renamed or deleted files surface the normal
“no longer available” message.

## Co-editing and presence

Shared **edit** links, the owner and multiple guest tabs use the same OnlyOffice
document key until a save advances the version. OnlyOffice's native participant
list provides co-editing presence; Alt8Mail sets distinct user IDs and display
names for owners and verified guests. Writable sessions send the documented
`coEditing` object (`mode: fast`, `change: true`); view-only sessions send
`change: false`.

## Alt8Mail AI assistant

The isolated editor page includes an Alt8Mail AI panel for signed-in users when
the organization has AI enabled and a model configured. It is an in-editor
assistant, not a separately installed OnlyOffice plugin.

- **Summarize**, **Rewrite**, **Translate**, **Continue** and **Ask AI** actions
  work on the editor's selected text.
- The editor Automation API connector reads the selection and inserts the result
  with `GetSelectedText` / `PasteText`; if insertion is unavailable the result can
  still be copied.
- Requests go to `POST /api/office/ai`, which uses the same tenant AI provider,
  model, endpoint and custom system prompt as the webmail AI assistant. The real
  DeepSeek or other OpenAI-compatible configuration is not replaced.
- Guest Office links do not receive the AI panel.
- Selected text is sent to the organization's AI provider; the panel states this
  explicitly. Review generated text before inserting it.

## Nginx routes

The webmail site needs the isolated editor host and longer API timeouts:

```nginx
location ^~ /api/office/ { ... proxy_read_timeout 180s; }
location ^~ /office-editor { ... dedicated CSP ... }
```

New installs use the updated site template. Existing installs receive
`/office-editor` through the System Control public-route repair snippet on the
next start. Web Net regenerates both locations for managed sites. The editor
page CSP allows the OnlyOffice browser API and document iframe while the main
mail shell keeps `script-src 'self'`.

## Secrets and security

- The JWT secret is generated by the agent and stored at
  `/etc/a8m/office-jwt-secret`, `root:a8m`, `0640`. It is never stored in the
  webmail database or returned by an API.
- The agent token is stored at `/etc/a8m/office-agent-token` (`root:a8m 0640`
  locally; `root:root 0600` on a remotely bootstrapped host).
- A remote SSH private key or password entered in the Control Plane is sealed
  with AES-256-GCM using `CONTROL_SECRET_KEY`; it is never returned by the API.
  The first SSH preflight only reports the host-key fingerprint and executes no
  remote commands until the operator trusts it. Later connections require the
  pinned fingerprint.
- The Control Plane does not keep a general-purpose remote shell. It runs a
  fixed set of preflight/bootstrap commands and then uses HTTP-over-SSH to the
  narrow agent API on remote loopback.
- The Office agent has no general-purpose Docker or shell endpoint. It only
  accepts the lifecycle operations in `backend/internal/officeagent`.
- Content and callback URLs are HMAC-signed capabilities bound to the file or
  document, user, tenant and expiry. They are not session cookies.
- Callback requests must carry a valid HS256 JWT signed with the shared secret
  in addition to the signed callback URL. Missing or invalid JWTs are rejected.
- The callback download is limited to 100 MB, HTTP(S) only, with a redirect cap,
  and the result must have the magic bytes of the expected Office format.
- Guest Office access is bound to an active share link, its recipient check, its
  view/edit permission and its expiry. Guest saves re-check the live share row,
  and every guest open/save is audited against the owner.
- The AI panel sends only the text the user selects (plus the instruction) to the
  organization's configured AI provider. Guests do not get the AI panel.
- The gateway certificate/key paths must be under `/etc/letsencrypt/live` or
  `/etc/ssl`.

`GET /api/office/config` returns only:

```json
{
  "enabled": true,
  "ready": true,
  "publicUrl": "https://office.example.com",
  "status": "running",
  "version": "9.4.0.1",
  "secretConfigured": true,
  "mode": "editor",
  "formats": {
    "word": ["doc", "docx", "odt", "rtf", "txt"],
    "cell": ["csv", "ods", "xls", "xlsx"],
    "slide": ["odp", "ppt", "pptx"],
    "pdf": ["pdf"]
  },
  "policy": {
    "internalSharing": true,
    "ai": true,
    "dlpOnSave": true,
    "versionRetention": 0
  }
```

`ready` requires `enabled`, a running container, a healthy recent agent check, a
readable JWT secret, a valid Office public URL and a valid webmail public URL.

Office is disabled in delegated mailbox windows.

## What comes next

Remote Office hosts are managed through the same narrow agent over an SSH
tunnel. Future work can add mTLS as an alternative transport, automated
installation of missing remote packages, and per-document review assignments on
top of the version comparison endpoint. The remote agent never exposes a raw
Docker socket or a public lifecycle API.
