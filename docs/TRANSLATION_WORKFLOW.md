# Alt8Mail translation workflow

Status: Phase 4 production pipeline.
Date: 2026-11-14.

Machine translation seeds drafts; it never edits a runtime catalog. A locale
reaches the language selector only after a reviewer promotes it. All 33 target
catalogs were reviewed, promoted and certified on 2026-11-14; the workflow
below remains the process for future string batches and new locales. The pipeline
runs against a local Ollama model, so source strings and customer-facing copy
do not leave the build machine.

## File layout

| Path | Role |
| --- | --- |
| `locales/en.json` | Canonical source; the only place new keys are authored. |
| `locales/<catalog>.json` | Reviewed runtime catalog for a locale. |
| `locales/drafts/<catalog>.json` | Proposed catalog: reviewed keys preserved, missing keys machine-translated. |
| `locales/drafts/<catalog>.meta.json` | Draft provenance: model, source hash, counts, failed keys. |
| `locales/manifest.json` | Locale rollout state: `planned`, `draft`, `reviewed`, `enabled`. |
| `public/locales/` | Generated runtime copies. Never edit by hand. |
| `artifacts/i18n-review/` | CSV/Markdown/HTML/JSON review package (git-ignored). |

`public/locales/` is only generated by `scripts/i18n-sync.mjs`. Runtime
coverage, fallback and plural rules live in `public/i18n.mjs`.

## Pipeline

1. **Author** new keys in `locales/en.json`. Keep placeholders, plural objects
   and the surface-oriented `mail.*` / `tasks.*` naming convention.
2. **Seed** machine drafts:

   ```bash
   npm run i18n:draft -- --locale de,fr,ja --model gemma4:latest
   npm run i18n:draft -- --wave 1,2 --batch 24
   npm run i18n:draft -- --locale all --batch 24
   ```

   Drafts are resumable. Each batch is written atomically, so an interrupted
   run continues from the last completed batch. `--repair` retranslates
   invalid keys and plural entries that are missing CLDR categories;
   `--force` retranslates machine keys while preserving reviewed live values;
   `--strict-plurals` rejects values that miss a required category; `--limit` is
   for spot checks. Arabic and Russian often need the larger local model for
   full plural coverage: `--model qwen3.6:latest --strict-plurals`.

3. **Inspect** coverage and missing keys:

   ```bash
   npm run i18n:status -- --draft
   npm run i18n:status -- --draft --missing de
   ```

4. **Export** the review package:

   ```bash
   npm run i18n:review -- --locale de
   ```

   This writes a spreadsheet (`csv`), reviewer summary (`md`), a side-by-side
   HTML review sheet and a machine-readable package (`json`) under
   `artifacts/i18n-review/`.

   A complete draft can be marked as rollout state `draft` without enabling it:

   ```bash
   npm run i18n:mark-drafts
   ```

5. **Review** the locale. Fix values in
   `locales/drafts/<catalog>.json` directly, or import a corrected file from
   the translation vendor. Re-run `node scripts/i18n-check.mjs` until it
   passes.

6. **Promote** after sign-off:

   ```bash
   node scripts/i18n-promote.mjs --locale de --check
   node scripts/i18n-promote.mjs --locale de --reviewed-by "Reviewer name"
   node scripts/i18n-promote.mjs --locale de --reviewed-by "Reviewer name" --enable
   ```

   Promotion requires 100% key coverage, exact placeholder sets, valid plural
   forms and a draft generated from the current `en.json`. Without
   `--reviewed-by`, the catalog is written with status `draft` and the locale
   stays disabled. `--enable` is refused without a reviewer.

7. **Regenerate** runtime copies and verify:

   ```bash
   npm run i18n:sync
   npm run i18n:check
   npm run test:i18n:e2e
   ```

## Machine-translation limits

The draft model is a local general-purpose model, not a dedicated translation
engine. Expect literal or contextually wrong terms, inconsistent inbox
terminology and weak handling of very short labels. The pipeline therefore
keeps drafts outside the runtime, validates structural integrity only, and
requires native review before promotion. Never copy a draft into
`locales/<catalog>.json` by hand; use the promote script so the source hash,
status and coverage stay consistent.

## Quality gates

`scripts/i18n-check.mjs` fails the build when:

- a catalog or draft contains a stale key;
- placeholders do not match `en.json` exactly;
- a plural object is missing `other` or has an unknown form;
- a referenced `t()`/`data-i18n` key is missing from `en.json`;
- `public/locales` is out of sync with `locales/`.

Promotion requires the plural categories the UI can select for counts 0-10
(Russian `few/many`, Arabic `zero/two/few/many`) without blocking on rare CLDR
categories such as French `many` at one million. Plural `one` and `two` forms
may omit `{count}` when the language expresses the numeral inherently; every
other placeholder stays mandatory. It warns when a locale is missing CLDR plural
categories or a draft contains keys not yet in the source. Draft values identical to English are reported in
the review package; brands and acronyms are allowed, everything else is a
review flag.

The `en-XA` pseudo-locale remains the UI expansion check for clipped layouts
and missing catalog keys.

## Review checklist

- Navigation, mailbox, authentication, security and billing copy reads
  naturally to a native speaker.
- Placeholders (`{name}`, `{count}`), HTML tags and line breaks survive
  unchanged.
- Brand names and technical acronyms stay untranslated: Alt8Mail, SPF, DKIM,
  DMARC, TLS, IMAP, SMTP, OAuth, SAML, SSO.
- Plural forms use the right CLDR categories for the locale.
- Date, time, number and currency examples fit the locale and regional
  preferences.
- Long labels do not clip in webmail, compose, settings, Admin or Control.
- RTL locales are checked with the Arabic pseudo-layout test at 360px.

## Rollout waves

| Wave | Locales |
| --- | --- |
| 1 | Existing catalogs: ar, de, fr, es, pt, nl, it (complete coverage first) |
| 2 | ja, zh-Hans, ko, ru |
| 3 | he, hi, tr, pl, sv, da, nb, fi |
| 4 | bg, cs, el, et, hr, hu, id, lt, lv, ms, ro, sk, sl, uk |

Locale release state is data, not code. A locale marked `draft` stays out of
the selector; a locale approved as community/beta must still be explicitly
recorded in the manifest and release notes.

## Full-core expansion

The original shell catalog was expanded on 2026-11-14 to cover every static,
non-dynamic product string: `public/app.js`, `public/index.html`, the extracted
`public/src` modules, the public mobile upload page and the server-message
catalog. Text nodes and visible attributes in `index.html` carry
`data-i18n`/`data-i18n-placeholder`/`data-i18n-title`/`data-i18n-aria-label`/
`data-i18n-alt` markers; dynamic server values (names, addresses, counts,
provider metadata and user content) stay untranslated by design.

`npm run i18n:lint --fail` is the regression gate for the webmail surfaces and
must report zero candidates. The expanded catalog is larger, so
`i18n-perf --fail` budgets the single locale a browser loads rather than the
size of the whole repository catalog set.
